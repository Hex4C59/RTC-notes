# 音视频同步

> [!tip] 阅读提示
> **前置：** [[时钟与时间戳]]、[[RTCP]]、[[播放器队列与主时钟]]；抖动侧见 [[NetEQ]] / [[抖动缓冲]]。
> **初读：** 先读“一句话说明”“为什么不能直接比较 RTP 时间戳”“播放调度”和“同步误差”。
> **深入：** 漂移补偿、故障与端到端测量在长通话或切层排障时再读。

## 一句话说明

音视频同步先把不同 RTP 时钟域映射到共同参考时间，再依据本地播放主时钟安排呈现，使同一事件的声音与画面落在可接受偏差内。它不负责消除网络抖动本身，也不等于“RTP 时间戳相等”。

## 问题边界

- **上游：** 每路 RTP 时间戳、RTCP SR 的 RTP/NTP 对、本地到达/解码/渲染时间、主时钟选择。
- **下游：** 音频连续播放节奏、视频等待/追赶/丢帧决策、对外暴露的 A/V offset 指标。
- **易混淆：**
  - 同步 ≠ 低延迟；可以把两边一起拖晚却“对齐”。
  - RTT / candidate-pair RTT ≠ 口型偏差。
  - 内部计划呈现时间 ≠ 扬声器/显示器真实出声出画时间。

## 核心机制

1. 用 RTCP SR（及必要估计）把各流 RTP 时钟映到共同参考。  
2. 选定主时钟（常为音频）。  
3. 计算从属流（常为视频）相对主时钟的目标呈现时刻。  
4. 在死区内不动作；持续偏差则小步校正；硬阈值才丢帧/重置。  
5. 长通话估计频偏（ppm），避免一次对齐后慢慢跑偏。

## 为什么不能直接比较 RTP 时间戳

音频 RTP 时钟常跟采样率，视频常用 90 kHz；初始值还随机。因此 `audioTs - videoTs` 无物理意义。

SR 提供观测对：

```text
(RTP timestamp, NTP / 参考墙钟采样)
```

多样本可估偏移与频率。SSRC 切换、重启、回绕要换代次。SR 稀或缺时，可用到达时间临时维持，但稳定性下降。

## 播放调度

```text
jitter buffer ready
  -> decode
  -> sync vs master clock
  -> audio: continuous device pull
  -> video: wait | present | drop late
```

1. 缓冲决定“何时可播”。  
2. 解码给出媒体时间。  
3. 同步控制算目标呈现。  
4. 音频按设备节奏出样；视频可等、可追、可丢。  
5. 校正限步长，避免跳变。

音频常作主时钟（断裂更敏感、设备持续耗样），但非协议强制。

## 同步误差

定义需在监控里写清符号，例如：

```text
A/V offset = 视频实际呈现 − 对应音频实际播放
```

它包含两侧 jitter buffer、解码排队、渲染队列、设备输出延迟——不能只从 RTP 推。

| 策略 | 何时用 | 风险 |
| --- | --- | --- |
| 死区忽略 | 小偏差 | 阈值过大则“一直差一点” |
| 小步调视频等待 | 持续偏差 | 过慢则长期拖尾 |
| 丢晚到视频帧 | 超出硬阈值 | 卡顿感 |
| 音频微伸缩 | 慢漂移 | 听感伪影 |
| 重置映射 | SSRC/时钟跳变 | 瞬态跳动 |

## 时钟漂移

采集端、播放设备、系统单调钟都可能有 ppm 级频偏。开始对齐后，数十分钟可积出可见口型差。

- 偏差**线性变大**：优先查频率估计/设备漂移。  
- 抖动期**突变**：优先查缓冲目标、映射重置、切层时间线。  

音频微重采样/时域伸缩与视频调度要配合，避免一边补漂移另一边猛丢帧。

## 与缓冲、切层的耦合

- [[NetEQ]] 抬高音频目标延迟会改变主时钟相位，视频若不跟着调，口型会瞬偏。  
- 视频升层/换 SSRC：新时间线要与旧输出衔接，否则“每次切层跳一下”。  
- 网络恢复后音频快速排空、视频仍高缓冲：会出现“声音已正常、画面仍拖”。  

统一看：两侧 current/target delay + A/V offset 曲线。

## 工程要点

- 分别记录：捕获、解码完成、计划播放、实际呈现（能测到设备侧更好）。  
- 校正死区与最大步长产品化标定，不照搬单一“±40 ms”教条当唯一真理。  
- 后台/熄屏/路由切换后重估映射，勿沿用过期 SR。  
- 多路视频（共享屏+摄像头）时明确以哪路与音频对齐。

## 常见误区与故障表现

- **开局齐、越聊越不对：** 漂移未补偿或时钟频率用错。  
- **切层就跳：** 新层时间戳/SSRC 未衔接。  
- **弱网恢复后长期不同步：** 两侧缓冲恢复策略不一致。  
- **Stats 说同步好但听感怪：** 未计入真实显示器/耳机链路延迟。  
- **用 RTT 当口型指标：** 量错对象。

## 观测与验证

- 指标：A/V offset（P50/P95）、两侧 jitter buffer、解码队列、音频伸缩量、映射重置次数。  
- 素材：声光同步测试源；尽量从扬声器+屏幕外测。  
- 注入：抖动、丢包、带宽阶跃、长通话、SSRC/层切换、设备切换、前后台。  
- 成功：偏差回到死区，且恢复时间可接受。

## 具体例子

通话 40 分钟后口型慢半拍。曲线显示 offset 近似线性 +0.5 ms/min（约 8 ppm 量级累积）。根因是只在开局用单次 SR 对齐、未做频偏跟踪。修复：用多样本估频偏，音频侧做缓慢重采样，视频死区跟随；长稳后 offset 回到死区。
