# 视频编解码

视频编码把一组有时空相关性的图像压缩为可传输、可解码的码流。典型编码器通过预测、残差变换、量化和熵编码去除空间与时间冗余；RTC 还要同时控制编码延迟、码率波动、恢复速度和终端资源。

## 定义

视频帧不是总能直接对应一个网络包：一帧可以包含多个切片/NAL 单元，一个 NAL 单元也可能需要分片发送。解码器按码流的参考关系重建图像，再交给渲染或后续滤镜。

## 核心机制

- YCbCr 与色度抽样决定像素平面、色度分辨率和带宽；采集、缩放、编码与渲染之间的格式转换会影响质量和 CPU。
- 帧内与帧间预测利用空间邻域和参考帧生成预测，残差再进入变换、量化与熵编码。
- GOP 与参考帧决定随机接入、错误传播、B 帧重排序和关键帧成本；H.264/HEVC 还会按各自的块结构和工具扩展实现。

## 工程要点

- 分辨率、帧率、码率、QP/量化参数、GOP 和参考帧数量共同决定质量、延迟和资源；不能只用平均码率评价实时编码。
- RTC 低延迟配置通常减少前瞻、限制重排序和关键帧间隔，并让编码器能快速响应带宽估计与拥塞控制。
- 参考帧损坏可能造成连续画面损伤；按截止时间选择 NACK/RTX、FEC 或 PLI/FIR，恢复后还要观察关键帧引起的码率峰值。
- 多方通话中可结合 Simulcast 或 SVC，但要把编码层、服务端选层、反馈关联和解码能力一起验证。

## 问题边界

- 视频编码负责从像素帧生成压缩码流；采集、颜色转换、RTP 组包、拥塞控制、解码和渲染分别有自己的队列与错误边界。
- “画质好”不能脱离分辨率、帧率、码率、延迟、设备资源和丢包恢复来判断。文件离线编码的最优配置不一定适合双向通话。
- 平均码率/平均帧率只能描述长期均值，无法表示关键帧峰值、编码 P99、首帧时间和突发卡顿。

## 数据结构与流水线

发送端通常经历：采集帧 → 像素格式/缩放 → 预处理 → 编码器 → 访问单元/NAL → RTP packetizer → pacer。接收端经历：RTP 重排/组帧 → 解码器 → YCbCr/RGB 转换与缩放 → frame queue → 渲染。每一层都应保存 frame id、PTS、分辨率、码率和所有权。

| 对象 | 主要字段/边界 | 典型问题 |
| --- | --- | --- |
| 原始帧 | width/height/pixel format/PTS | stride、色彩范围、设备时钟 |
| 编码帧 | frame type、size、reference | QP、GOP、前瞻、关键帧 |
| NAL/AU | 语法单元和访问边界 | 分片、参数集、丢失依赖 |
| RTP 包 | seq/timestamp/SSRC/payload | MTU、乱序、丢包、反馈 |
| 解码帧 | planes/PTS/format | buffer 引用、重排、渲染截止 |

## 编码决策步骤

1. 依据设备能力、窗口和网络预算确定分辨率、帧率、像素格式和层数。
2. 预处理/缩放后送入编码器，按延迟模式和参考结构选择预测与 GOP。
3. 率失真控制调整 QP、帧率、分辨率或层，输出编码帧并计算峰值。
4. 按 codec payload 规范拆分为 RTP，pacer 结合带宽估计发送。
5. 接收端按截止时间选择等待、重传、FEC、丢弃或关键帧恢复，再将解码帧同步呈现。

## 时间与缓冲关系

端到端视频延迟包括采集周期、预处理、编码前瞻、编码队列、发送 pacer、网络/jitter buffer、组帧、解码重排、渲染等待。提高 frame queue 可以吸收抖动，但会增加互动延迟；降低缓冲可减少延迟，却更容易丢帧。关键帧请求和层切换会瞬时改变码率/队列，必须纳入预算。

## 关键参数与取舍

- 分辨率/帧率：清晰度、运动流畅度、带宽和编码 CPU 的取舍。
- target/max bitrate、QP range、VBV/发送队列：质量与实时稳定性的取舍。
- GOP、B 帧、参考帧、lookahead：压缩效率与恢复/延迟的取舍。
- Simulcast/SVC、硬件/软件编码：适配面、上行开销、功耗和互操作的取舍。

## 常见误区与故障

- 一个视频帧等于一个 RTP 包：实际一帧可含多 NAL/切片，一个 NAL 也可分片。
- 码率不足只降低 QP：实时编码器还可能降分辨率/帧率、丢帧或切层，策略要可观测。
- 关键帧越频繁越抗丢包：频繁关键帧会提高峰值码率，反过来造成拥塞和更多丢包。
- 只看接收渲染 FPS：编码/网络/解码/渲染各层都可能丢帧，必须按 frame id 和 PTS 对账。

## 可观测与验证

- 每层记录采集/编码/发送/接收/解码/呈现时间、帧类型、QP、bytes、队列深度、丢帧、关键帧请求和恢复时间。
- 用静止、摄像头运动、屏幕文字、场景切换、带宽阶跃、随机/突发丢包和设备过载测试。
- 输出基线与改动后的 P50/P95/P99 延迟、码率、卡顿、关键帧大小、CPU/GPU、功耗和画质指标，避免只报平均值。

## 具体例子

720p/30 fps 视频约每 33.3 ms 产生一帧，但编码器前瞻、pacer 和接收 jitter buffer 可能各增加等待。网络突然降速时，先降低层或帧率可能比立即请求关键帧更稳；若参考已损坏，再根据 RTT 和剩余播放时间决定有限重传还是 PLI/FIR。
