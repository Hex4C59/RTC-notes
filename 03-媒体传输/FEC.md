# FEC

> [!tip] 阅读提示
> **前置：** [[丢包恢复策略]]；对照 [[RTX]]、[[NACK]]。
> **初读：** 读到「初读到此为止」就停。弄清：FEC 用提前发的冗余换「不等一轮反馈也能修」，不是可靠传输保证。
> **深入：** 保护块状态、预算联动、观测实验在联调与弱网排障时再读。

## 一句话说明

FEC（Forward Error Correction）在原始媒体之外发送可计算的冗余符号，使接收端在不等待反馈往返的情况下恢复一定范围的丢失数据。它是恢复手段，不是可靠传输保证；超出保护能力的丢失仍需 [[RTX]]、PLC 或关键帧刷新。

## 先记住这三句

1. FEC 是 **先发冗余、收端自己算回来**，不用先等 NACK 再绕一圈；但收集保护块本身仍可能加点延迟。
2. 保护有上限：块里丢太多就修不回来，还得走 RTX / PLC / [[PLI 与 FIR]]。
3. 冗余要占带宽预算；链路已经挤时盲目开 FEC，可能让原始媒体也一起更堵。

## 它怎么工作（初读版）

```text
编码帧 -> 媒体包
  -> 按保护窗口收集一批原始包
  -> FEC 编码器生成冗余包（带关联元数据）
  -> 原包 + 冗余一起进 Pacer
  -> 收端凑齐保护块
  -> 缺失数 ≤ 冗余能力 -> 重建 -> 组帧/解码
  -> 否则 -> RTX / PLC / 刷新
```

1. 发送端把编码帧切成媒体包，按保护窗口收齐若干原始包。  
2. FEC 编码器从这些包生成冗余包，并写上「哪些原包、怎么关联」的元数据。  
3. 原包与冗余一起进入 Pacer；接收端按序号与保护块状态收集。  
4. 缺失仍在能力内就重建，再组帧解码；超能力就退到重传或替代输出。

> [!example] 小例子
> 一个保护块有 10 个原始包、再发 2 个独立冗余包。若只丢 1～2 个，多半能算回来；若同时丢 3 个，冗余不够，仍要 RTX、PLC 或视频刷新。数字只是示意块级能力，不是所有 FEC 算法的固定参数。

## 和 RTX 怎么选（直觉）

| 条件偏向 | 更倾向 |
| --- | --- |
| RTT 大、反馈晚、单包/短突发可覆盖 | FEC |
| 个别缺口、缓存仍在、截止内可赶回 | NACK + RTX |
| 参考链已断、块级修复无望 | PLI/FIR 或丢弃+PLC |

同一会话可以组合，但冗余与重传字节都要扣进媒体预算，并用恢复后卡顿/延迟验证净收益，而不是只看「恢复包计数」。

带宽也要想一下：原始媒体约 1,000 kbit/s、冗余 20% 时，仅媒体+冗余约 1,200 kbit/s，还没算 RTP/SRTP/UDP/IP/RTCP。链路无余量时硬开 FEC，可能触发过载，[[QoS 与 QoE]] 反而变差。

```text
是否启用 ≈ f(剩余播放时间, 预计重传 RTT, 突发长度, 额外流量, 媒体重要性)
```

## 问题边界

- **上游：** 编码帧切包、保护窗口选择、历史丢包/突发模式、RTT、剩余播放时间、统一发送预算（[[带宽分配]]）。
- **下游：** 保护块重建后的原始包、组帧/解码/播放；重建失败后的 RTX/PLC/刷新退路；[[QoS 与 QoE]] 上的卡顿与延迟变化。
- **易混淆：**
  - 「无需等 RTT」≠「零延迟」；收集保护块与等待冗余本身可能增加发送或播放等待。
  - FEC 能恢复 ≠ 任意丢包都能恢复；受块边界、冗余强度与突发模式限制。
  - 冗余比例写在配置里 ≠ 线上真实开销；还要计 RTP/SRTP/UDP/IP/RTCP。
  - 恢复包数量对 ≠ 解码一定成功；元数据关联错或关键参考已过期仍会失败。
  - FEC 与 RTX 不是互斥标签，而是同一预算下的工具选择（见 [[丢包恢复策略]]）。

## 保护块状态

| 状态 | 含义 |
| --- | --- |
| 原始包已到 | 媒体包本身可用 |
| 冗余包已到 | 符号可用于重建 |
| 已重建 | 由 FEC 算出的等价原包，须去重后入组帧 |
| 已过期 | 超过播放/块等待上限，不再等符号 |

保护块要保存原始包范围、包数、符号大小、冗余数量与已收符号集合；状态不能跨 SSRC 或编码层混用。RTP 序号、时间戳、SSRC 仍来自原始媒体；FEC 元数据只说明如何恢复，不改变恢复后包的媒体时序。

## 工程要点

- **随模式调参：** 按历史丢包率、突发长度、RTT 与媒体截止选择保护比例；优先覆盖关键参考或仍有播放价值的媒体。
- **统一预算：** 冗余必须进入统一发送预算与 Pacer；不能因为「前向」就无限插入队列。拥塞时应有明确优先级与降冗余路径。
- **接收路径统一：** 先乱序/去重，再按保护块重建；重建包必须重新进入统一序号检查、组帧与解码队列，且只消费一次。
- **块边界与版本：** 保护参数变化要带版本或块边界，避免把前一组冗余解释到后一组媒体上。
- **等待上限：** 保护块必须有容量与时间上限；长时间等更多符号会把 FEC 变成额外播放延迟。
- **失败退路：** 突发超过能力时安全转入 [[RTX]]、PLC 或 [[PLI 与 FIR]]，并保留可观测原因。

## 常见误区与故障表现

| 误区 | 故障表现 / 排查 |
| --- | --- |
| FEC 能恢复任意丢包 | 突发超能力仍花屏；查块大小与冗余强度 |
| 无需反馈所以无延迟 | 卡顿/延迟上升；查保护块等待与发送收集 |
| 只开 FEC 不看预算 | 开启后更卡；查线上码率、Pacer、编码器是否联动降码 |
| 恢复数对但解失败 | 元数据关联错、序号未还原、关键参考过期 |
| 与 RTX 抢预算无协调 | 双重开销挤新媒体；查 [[带宽分配]] |

## 观测与验证

**一起看：** 原始丢包、FEC 恢复数、恢复失败数、FEC 字节占比、恢复耗时、晚到丢弃、播放冻结；对照无 FEC / 仅 RTX / FEC+RTX。

**四组实验（固定媒体码率与统计窗口）：**

1. 随机单包丢失  
2. 连续突发丢失（超过与不超过冗余能力各一档）  
3. RTT 增大（突出「免等反馈」收益是否真实）  
4. 带宽骤降（验证冗余是否触发过载）

**最小验收：**

- 抓包能确认保护块边界、原始包范围与冗余关联。  
- 分别报告原始丢包、FEC 重建与重建失败，而不是只报最终解码结果。  
- 证明恢复包未绕过 Pacer、预算与播放截止。  
- 超能力突发时有明确退路且不重复送解码器。

复盘：当前保护块最大可恢复丢失数是否随码率/突发变化？FEC 额外字节与块等待是否分别计入预算与延迟？
