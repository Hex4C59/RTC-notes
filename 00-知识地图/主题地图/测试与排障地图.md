# 测试与排障地图

## 从现象到阶段

- [[RTC 故障树]]：把用户现象转换成会话、连接、传输、媒体和呈现判断。
- [[WebRTC 状态机诊断]]：对齐业务、信令、ICE、DTLS 和媒体状态。
- [[ICE 与 TURN 诊断]]：定位候选收集、检查、提名、中继和网络回退。

## 三类证据

- [[Stats 指标与故障映射]]：把累计统计转换成阶段性时间序列。
- [[webrtc-internals]]：查看浏览器 API 事件、状态和指标曲线。
- [[抓包分析]]：验证网络报文、时序、流标识和反馈事实。
- [[网络仿真]]：在可控条件下注入弱网并重复验证修复效果。

## 建议排障顺序

先用故障树把现象限定到方向和阶段，再建立会话状态时间线；随后用 Stats 判断计数在哪一段停止，通过 webrtc-internals、服务端日志和抓包互证，最后在隔离环境用网络仿真复现与回归。

## 掌握标准

- 每个结论都能指出时间窗口、方向、流标识、版本和至少两类相互独立的证据。
- 能区分“没有发送”“没有到达”“没有解码”和“没有呈现”。
- 修复后能在同一条件下验证体验、协议指标和资源副作用。
