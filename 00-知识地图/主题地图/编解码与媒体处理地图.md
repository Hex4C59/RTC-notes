# 编解码与媒体处理地图

## 关系速览

```mermaid
flowchart LR
    Source["麦克风 / 摄像头"] --> Raw["PCM / YCbCr 原始帧"]
    Raw --> Pre["预处理<br/>重采样、缩放、语音处理"]
    Pre --> Enc["编码<br/>Opus/AAC 或 H.264/HEVC"]
    Enc --> Bitstream["压缩码流与时间戳"]
    Bitstream --> Packet["容器或网络负载"]
    Packet --> Dec["解复用、解码"]
    Dec --> Sync["队列、同步与呈现"]
```

媒体域按数据形态分成三条学习路径，避免把编解码原理、容器时间和播放器 API 混成同一层：

- [[音频技术地图]]：PCM、感知编码、AAC/Opus 与语音处理。
- [[视频编码地图]]：像素表示、预测、变换、参考结构和可伸缩编码。
- [[FFmpeg 与媒体处理地图]]：容器、时间基、Packet/Frame、解码状态机和播放队列。

## 三条路径怎样衔接

音频和视频路径解释“原始媒体如何变成压缩码流”；FFmpeg 路径解释“码流怎样被容器组织、解码成帧并按时间播放”。RTC 还会把编码参数接入网络反馈闭环，因此学习时要持续追问：一个参数改变了码率、算法延迟、错误扩散还是解码复杂度？

## 掌握标准

- 能区分原始样本/像素、编码帧、NAL/音频包、AVPacket、AVFrame 和容器。
- 能解释 PTS、DTS、RTP timestamp 和本地播放时钟的不同用途。
- 能根据实时性、质量、终端能力和弱网条件选择编码与处理策略。

编码输出如何进入网络见 [[媒体传输地图]]，网络如何反向调节编码见 [[网络质量地图]]，终端如何采集和呈现见 [[客户端工程地图]]。
