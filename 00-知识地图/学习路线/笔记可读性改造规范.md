# 笔记可读性改造规范

[[RTC 知识总览|返回阅读首页]] · [[AGENTS]] · [[99-模板/RTC 概念笔记模板|概念笔记模板]]

本文约定：**在不削弱工程深度**的前提下，让零基础也能按「第一次阅读」走通。批量改笔记前先按本页执行；与 [[AGENTS]]、概念模板冲突时，**以 AGENTS 的导航/图谱/准确性要求为准**，本页只补「可读性分层」。

## 1. 目标与非目标

**目标**

- 第一次打开一篇概念笔记，能在 **3–8 分钟**内抓住「是什么 / 解决什么 / 在全链路哪一环」。
- 初读路径清晰：读到哪里停、下一站去哪，不靠猜。
- 工程细节仍在原笔记里，方便第二轮与排障查阅。

**非目标**

- 不把知识库改成短视频文案或删掉机制、字段、状态机。
- 不整库一次性重写；不改动 `90-参考资料/` 全文。
- 不破坏 [[概念阅读导航链]]、专题「上一篇/下一篇」、Obsidian `[[双向链接]]`。
- 不把多篇内容合并成「一本大教程」；仍保持一概念一篇。

## 2. 改造原则（五条）

1. **分层，不删减**：初读区白话；工程区保留深度。用分隔线切开，不把难段物理删掉。
2. **例子优先于术语表**：能说明机制的小例子、对照表，放在初读区；SSRC、P99、状态机细节放分隔线后。
3. **一次只引入必要新词**：初读区出现术语时，括号给半句人话；详情用链接，**禁止整段搬运**邻篇。
4. **导航不断**：改结构可以调章节顺序，但文末「阅读导航 / 第一次阅读下一站 / 图谱关系」必须保留且与导航链一致。
5. **可回滚**：每批改动前备份（`原名.bak-时间戳`），一批只覆盖约定目录范围。

## 3. 概念笔记标准骨架（改造后）

在现有模板之上，统一为：

```text
frontmatter（aliases / tags / type / status）
# 标题
[!tip] 阅读提示（前置 / 初读停哪里 / 深入何时读）
## 一句话说明
## 先记住这三句          ← 改造新增；不足三句可写两句，勿灌水
## … 初读正文 …         ← 故事、通路图、对照表、小例子
[!warning] 初读到此为止  ← 改造新增；硬分隔
## … 工程展开 …         ← 原模板：问题边界/核心机制/字段/流程/误区/观测等
## 阅读导航
## 图谱关系
## 参考资料
```

说明：

- 若原文「问题边界 / 核心机制」本身就是白话且很短，可留在初读区；一旦出现字段清单、线程模型、P95/P99、SLA，**必须**放到分隔线后。
- 「先记住这三句」写**可复述的结论**，不写定义堆砌。
- 阅读提示里的「初读」必须写成：**读到「初读到此为止」就停**，并点名初读区应完成的一个小问题（例如「标出三个加延迟的位置」）。

### 分隔线固定文案

```markdown
---

> [!warning] 初读到此为止
> 上面这些已经够第一次阅读。下面是工程展开与排障细节（字段、指标、状态流），**第二轮或遇到具体问题时再读**；第一次直接点文末「第一次阅读下一站」即可。
```

允许按篇微调第二句，但标题 **「初读到此为止」** 不要改，便于全文检索与批处理。

## 4. 文风细则

| 场景 | 优先写法 | 避免 |
| --- | --- | --- |
| 初读区 | 因果句、生活类比、步骤列表 | 一上来堆协议缩写 |
| 术语首次出现 | `ICE（找一条能通的网络路径）` | 假设读者已知全部缩写 |
| 数量 | 带单位；标明「示意 / 以实测为准」 | 把示意写成保证值 |
| 链接 | `[[概念]]` + 半句为何相关 | 连续甩 5 个链接不解释 |
| 工程区 | 机制、边界、误区、观测 | 删掉「不好懂」的正确结论 |

区分易混概念时，初读区用一张小表即可（如 RTT ≠ 端到端延迟）；细规则进工程区。

## 5. 专题说明 / 知识总览

- **知识总览**：保留零基础首屏（建连 / 通路 / 媒体 + 三篇起步）；完整目录与「必须串起来的机制」标成可后读。
- **专题说明**：文首用「本专题要解决的问题」白话句；P0/P1、知识组统计可保留，但不要压过「先读哪几篇配套详解」。
- **主题地图 / Canvas**：不强制改画布；概念笔记初读体验优先。
- **通信时序图**：凡「左发送 / 右接收、箭头对打」的过程，按 [[时序图画法约定]] 用 Mermaid `sequenceDiagram`（图前「图在说什么」）；样板见 [[Offer Answer]]、[[RTP]]、[[NACK]]。
- **状态机 / 管线 / 结构图**：单端过程用 `flowchart` / `stateDiagram`（约定 §3.5），不要硬画成左右对打。

## 6. 批次与优先级

| 批次 | 范围 | 完成标准 |
| --- | ---: | --- |
| A（已部分完成） | 总览零基础首屏；第一次阅读前三篇 | 分隔线 + 先记住 + 例子在前 |
| B | 第一次阅读其余篇：`播放截止时间`、`时钟与时间戳`、`数据面与控制面` | 同 A |
| C | `01-基础` 剩余 + 导航链上紧随的会话/传输入门篇 | 同 A；抽查导航闭合 |
| D | `02` 会话与连接、`03` 媒体传输（按导航链，不按文件名一次全开） | 每篇初读 ≤ 屏高约 1.5 屏（手机可放宽） |
| E | 专题说明 01–16 入口白话 | 每页能 1 分钟内知道「读什么、练什么」 |
| F | `04`–`08` 按你实际学习进度按需 | 学到哪改到哪 |
| G（图示） | 时序图 P0–P2 + 状态机/NAT/线程 flowchart | 见 [[时序图画法约定]] 样板表 |
| — | `90-参考资料` | **不改** |

一批建议 **3–8 篇**，改完你抽读 1 篇反馈，再开下一批。

## 7. 单篇改造检查清单

改完一篇，作者自检：

- [ ] 阅读提示写清「停在分隔线」
- [ ] 有「先记住」（2–3 句可复述）
- [ ] 初读区有图或步骤或小例子；工程专有名词不喧宾夺主
- [ ] 有且仅有一处「初读到此为止」硬分隔
- [ ] 原文正确机制未删；只是后移或改写表达
- [ ] 「阅读导航 / 第一次阅读下一站 / 图谱关系 / 参考资料」仍在
- [ ] 若有过程图：时序图或 flowchart 选用正确，且图前有「图在说什么」
- [ ] 未把 `90-参考资料` 大段粘进正文
- [ ] 已备份 `*.bak-时间戳`
