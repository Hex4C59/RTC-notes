## 09.1 协议定位与固定头 · P0

### RTP 与 UDP 的关系

UDP 承载数据报；RTP 在媒体层补充序号、时钟、来源和负载解释信息，不保证可靠到达。

UDP 下方仍需要 IP 路由、链路层交付和物理信号传输。先沿 [[从 RTP 到网卡、路由器与物理链路]] 理解 MAC、ARP/NDP、网卡、交换机、路由器与 NAT，再进入 RTP 字段；这些下层机制共同影响包能否按时抵达。

终端接入网络时，还需要通过 [[DHCP]] 或静态配置取得 IPv4 地址、掩码、默认网关和 DNS。DHCP 成功只表示配置已发放，不代表信令、ICE 或媒体路径必然可用。

### 序号、时间戳与 SSRC

学习 16 位序号、32 位时间戳和同步源标识；SSRC 不能简单等同于用户账号。

### PT、Marker 与可变头

负载类型需要约定；Marker 语义随负载格式变化；解析时考虑 CSRC、扩展和填充。

### RTMP 在 TCP 上的推流与拉流

RTMP 用 Chunk 给 TCP 字节流建立消息边界，并用 `connect/createStream/publish/play` 管理直播发布与订阅；学习时要把传输连接、命令状态和媒体可解码状态分开。

### WebSocket 的消息边界与承载

[[WebSocket]]在 TCP 之上提供 Text/Binary message、Ping/Pong 和关闭握手。它可承载信令或自定义媒体，但上层仍要分别定义业务版本/幂等，以及媒体 codec config、时间戳、关键帧和有界背压。

### HTTP-FLV 长连接拉流

[[HTTP-FLV 拉流服务]]通过持续 HTTP 响应输出 FLV Header 与 Tag；HTTP 读取边界不等于 FLV Tag 边界，新观众还需要 codec config 和可解码关键帧。

**本组练习：** 从抓包解释 RTP 版本、序号、时间戳、SSRC、PT、Marker 与扩展长度；用 WebSocket 分片/背压实验区分 frame、message 和应用消息；再用 RTMP/HTTP-FLV 日志区分握手或 HTTP 建立、收到媒体、首个可解码关键帧和实际渲染。

**掌握标准：** 完成上述练习，能说明输入输出、状态、时间或资源边界，并用抓包、日志、样本或可复现操作解释至少一个异常结果。

**配套详解（先 RTP，后底层/旁路）：** [[RTP]] · [[UDP IP Socket 与 MTU]] · [[从 RTP 到网卡、路由器与物理链路]] · [[DHCP]] · [[TCP]] · [[WebSocket]] · [[RTMP 推流与拉流]] · [[HTTP-FLV 拉流服务]]。

## 09.2 发送与接收状态 · P1

### 序号回绕与扩展序号

测试 65535 → 0；排序、丢包检测和缓存索引不能只按普通整数大小比较。

### 乱序、重复与源切换

维护每个源的状态；区分重复包、晚到包、明显异常包和流重启。

### 安全的二进制解析

逐字段验证长度和范围；处理短包、损坏扩展、非法填充，避免越界读写。

**本组练习：** 用乱序、重复、截断和序号回绕数据检验接收解析与源状态。

**掌握标准：** 完成上述练习，能说明输入输出、状态、时间或资源边界，并用抓包、日志、样本或可复现操作解释至少一个异常结果。

**配套详解：** [[RTP 流标识与复用]]。

## 09.3 负载打包 · P1

### Opus over RTP

一个 RTP 负载装一个 Opus packet；该 packet 可含多个编码帧，时长要从正确语义确定。

### H.264 单包、聚合与分片

学习 Single NAL Unit、STAP-A、FU-A；先实现单包/FU-A，再按协商范围增加支持。

### MTU 与封装预算

RTP 分片应考虑 IP、UDP、RTP 扩展和 SRTP 等开销；应用分片不同于 IP 分片。

**本组练习：** 计算含 SRTP 和扩展的 MTU 预算，观察 H.264 大 NALU 的分片与重组。

**掌握标准：** 完成上述练习，能说明输入输出、状态、时间或资源边界，并用抓包、日志、样本或可复现操作解释至少一个异常结果。

**配套详解：** [[H264 RTP 负载格式]] · [[Opus RTP 负载格式]]（编解码本体见专题 07/08）。

## 09.4 扩展与互通 · P2

### 头扩展与流标识

认识 MID、RID、音量等扩展；扩展标识和含义来自协商，不可任意硬编码。

### RTP/RTCP 复用与 BUNDLE

理解一个传输上可有多个媒体源，收包端需要正确识别协议及媒体归属。

### 标准、抓包与互操作

本地自定义发送接收成功不代表标准互通；用抓包和独立实现核对线格式。

**本组练习：** 在协商信息与抓包之间核对 MID、RID、SSRC、PT 和复用规则。

**掌握标准：** 完成上述练习，能说明输入输出、状态、时间或资源边界，并用抓包、日志、样本或可复现操作解释至少一个异常结果。

**配套详解：** [[RTP 流标识与复用]]。

## 专题验收

写 RTP 编解包器，并测试正常头、CSRC、扩展、padding、短包和序号回绕；把一个大 NALU 分成 FU-A，再按乱序输入重组。

能从十六进制数据解释主要字段，并明确“一帧图像、一个 NALU、一个 RTP 包、一个 UDP 数据报”的不同边界；还能区分 TCP 读取、WebSocket message、HTTP 响应数据与 FLV Tag 的边界。

记录：所用版本与设备、输入与参数、正常结果、异常结果、证据位置、尚未解决的问题。没有实验记录时，不把目录勾选当作掌握证据。
