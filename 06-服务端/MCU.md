# MCU

## 一句话说明

MCU 在服务端解码多路媒体、完成混音或画面合成，再编码成单路或少量输出，以下行简单和统一布局换取服务端计算量与额外延迟。

## 核心机制

- 音频通常需要重采样、增益处理与混音；视频需要解码、缩放、布局合成和再编码。
- 输出流拥有新的编码状态、时间线和码率，不再是简单转发原发送者的码流。
- 适合传统终端互通、固定合成布局、集中录制或终端能力受限场景。

## 处理流水线

典型 MCU 流水线比 SFU 多出完整的媒体处理阶段：

1. 接收并解密多路 RTP，完成乱序整理、抖动处理和解码。
2. 把各输入转换到内部统一的采样率、像素格式、尺寸和时间基。
3. 音频执行电平估计、增益、静音和混音；视频执行裁剪、缩放、布局与叠加。
4. 按统一输出时钟生成音频块和视频帧。
5. 编码成目标终端支持的格式，再封装、加密并发送。

每个阶段都必须有截止时间。某一路迟到时，系统通常使用上一帧、占位画面、PLC 或直接跳过，不能让整个合成输出无限等待。

## 音频混合

- 输入可能具有不同采样率、声道数、增益和设备时钟，需要先重采样与对齐。
- 简单相加会削波，需进行增益预算、限幅或动态处理。
- “减去自己的声音”的 mix-minus 输出能避免参与者听到明显自声，但会增加输出组合数量。
- 大房间可以只混合活跃发言人，减少噪声与计算量，同时需要平滑切换避免听感突变。

## 视频合成

- 输入帧必须映射到统一合成时间轴，迟到帧可复用上一帧或显示占位状态。
- 裁剪与缩放要保持宽高比、像素格式、色彩范围和旋转信息。
- 固定布局输出只有一个编码视角，接收端无法像 SFU 那样自由选择单个发言人的原始高清流。
- 布局变化会改变画面复杂度，可能引发瞬时码率和编码延迟上升。

## 工程要点

- 容量受编解码分辨率、帧率、并发路数和硬件加速能力影响。
- 任何一路输入异常都不应阻塞整个混合流水线。
- 需要测量混合队列和再编码给端到端预算增加的时间。

## 时间与容量

MCU 的内部时钟决定何时产生下一块混音音频和下一帧合成视频。输入时间戳用于对齐内容，却不能直接作为输出 RTP 时间戳；输出是新的媒体源，应拥有连续的新时间线。

容量估算至少拆开：输入解码像素率、缩放/合成像素率、输出编码规格、音频混合路数和内存带宽。硬件编码器的“会话数”限制、像素吞吐和支持的 profile 也可能比 CPU 更早成为瓶颈。

## 常见故障与验证

- 全员音频爆音：检查混音增益、削波、格式转换和时间块缺失。
- 某一路卡顿拖累所有输出：检查流水线是否在等待该输入，以及是否有截止/占位策略。
- 合成画面延迟持续增加：检查解码、布局和编码队列是否有界，输出时钟是否被积压任务拖动。
- 音画逐渐漂移：检查输入时钟映射、重采样补偿和输出主时钟。
- 验收时分别测量接收、解码、合成、编码和发送时间，报告 P50/P95/P99，不能只报告端到端平均值。

## 场景示例

一个课堂录制可以向互动学员发送 SFU 个性化订阅，同时由 MCU 生成“老师 + 课件 + 字幕”的固定录制流。这样实时互动保持低延迟，录制端获得统一布局，但必须为 MCU 的额外延迟和故障设置独立隔离。
