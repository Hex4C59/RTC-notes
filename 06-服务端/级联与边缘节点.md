# 级联与边缘节点

## 一句话说明

级联把多个媒体节点组成跨地域转发拓扑，边缘节点让用户就近接入，以缩短最后一公里路径并把单房间或全局容量分散到多个故障域。

## 核心机制

- 调度层选择接入节点和跨节点路径；媒体层只复制必要流，避免全量洪泛。
- 跨节点需要传播发布、订阅、流标识和质量反馈，同时处理节点退出和路径切换。
- 级联层数减少单点带宽压力，却可能增加传播延迟、反馈折返和排障复杂度。

## 为什么需要级联

单中心 SFU 会让远端用户绕路，并把所有房间的进出流量集中到一个地域。边缘接入让客户端连接到网络更近的节点；级联只在节点之间传递确有订阅的媒体，从而控制跨区带宽和故障影响面。

常见形式包括：

- 星形：区域节点都连接中心节点，控制简单，中心链路容易成为瓶颈。
- 树形：媒体逐级复制，跨区流量可控，但路径更长且上游故障影响下游。
- 网状或按需直连：路径更短、冗余更多，路由和状态一致性更复杂。
- 分层混合：边缘负责接入，区域核心负责房间汇聚，录制/转码在独立节点进行。

## 按需传播流程

1. 用户在边缘节点发布媒体，节点注册发布及其编码层。
2. 另一区域出现订阅时，调度层计算跨节点路径。
3. 沿路径建立上游订阅，只传递该区域实际需要的最高层或依赖集合。
4. 下游订阅消失后，经过防抖和保持时间撤销跨区流，避免频繁开关。
5. 链路或节点故障时选择备用路径，并重建标识、反馈和关键帧状态。

若三个边缘都需要同一发布，靠近源端复制通常比源端发送三份完整跨区流更节省出口；但复制点也必须具备足够下行容量。

## 标识与反馈

- 跨节点协议要携带稳定的发布身份，不能只依赖可能改写的 SSRC。
- 每段链路可能有独立的拥塞控制、序列改写和重传缓存。
- 下游 NACK 应优先由最近缓存处理；无法恢复时再逐级向源端传播。
- 关键帧请求需聚合限速，跨区 RTT 较大时还要考虑请求是否赶得上播放截止时间。
- 端到端统计必须保存每段链路和映射，否则只能看到“边缘出站丢包”，无法定位损伤发生在哪一跳。

## 工程要点

- 为每条跨区链路设置容量、冗余、重连和回退策略。
- 观测必须能从用户订阅回溯到每一段节点与链路。
- 故障迁移要说明是否保持 SSRC/序列状态以及是否触发关键帧。

## 调度与故障策略

- 接入调度综合 RTT、丢包、节点余量、区域合规和房间亲和性，不应只按地理距离。
- 已建立通话是否迁移要权衡中断成本；新用户调到健康节点通常比强迁所有存量用户风险低。
- 跨区链路需设硬容量和准入策略，过载时先降低视频层或限制新订阅，避免无限排队。
- 控制面短暂不一致时，媒体面需要有明确租约或代次，防止双路转发和旧路由复活。

## 常见故障与验证

| 现象 | 可能原因 |
| --- | --- |
| 同区域正常、跨区卡顿 | 跨区链路拥塞、选层未下调、反馈 RTT 过长 |
| 切换后重复或跳帧 | 新旧路径重叠、序列/时间戳映射不连续 |
| 一处订阅导致全球复制 | 路由撤销失败、需求聚合或引用计数错误 |
| 边缘故障后长时间黑屏 | 备用路径未预热、关键帧未请求、旧代次未清理 |

演练应主动断开跨区链路或退出单个媒体节点，记录检测、路由收敛、首包、首个可解码帧和体验恢复时间，并确认恢复后旧路径资源被释放。
