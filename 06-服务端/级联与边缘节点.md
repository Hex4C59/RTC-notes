# 级联与边缘节点

> [!tip] 阅读提示
> **前置：** [[服务端架构地图]]、[[SFU]]、[[会议媒体路由与订阅]]。
> **初读：** 先读「一句话说明」「问题边界」「为什么需要级联」和「按需传播流程」。
> **深入：** 标识与反馈、调度故障策略与演练表，在跨区卡顿或切节点时再读。

## 一句话说明

级联把多个媒体节点组成跨地域转发拓扑，边缘节点让用户就近接入：缩短最后一公里，并把单房间/全局容量分散到多个故障域。目标是**按需复制**，不是把每路媒体洪泛到全世界。

## 问题边界

- **上游：** 接入调度、发布/订阅意图、跨区链路容量与合规。
- **下游：** 跨节点路径、按需订阅的最高层集合、故障切换与观测分段。
- **易混淆：**
  - 边缘接入近 ≠ 跨区媒体一定近（错误级联仍会绕路）。  
  - 有级联 ≠ 全量复制；撤销失败才会“一处订阅、全球搬运”。  
  - 边缘出站丢包 ≠ 损伤一定在边缘（可能在上游某跳）。  
  - 强迁所有存量用户 ≠ 总比只调新用户更安全。

## 核心机制

1. 调度层选接入节点与跨节点路径；媒体层只复制**有订阅**的流。  
2. 跨节点传播发布、订阅、流标识与质量反馈；处理节点退出与路径切换。  
3. 层数分散单点带宽，但增加传播延迟、反馈折返与排障复杂度。  
4. 每段链路可有独立拥塞、改写与重传缓存；端到端统计要分段。

## 为什么需要级联

单中心 SFU 让远端用户绕路，并把进出流量堆在一个地域。边缘接入就近；级联只在节点间传确有订阅的媒体，控制跨区带宽与故障面。

| 形态 | 优点 | 代价 |
| --- | --- | --- |
| 星形 | 控制简单 | 中心链路易成瓶颈 |
| 树形 | 跨区流量可控 | 路径更长；上游故障影响下游 |
| 网状/按需直连 | 路径短、冗余多 | 路由与一致性复杂 |
| 分层混合 | 边缘接入 + 区域汇聚；录制/转码独立 | 对象与权限边界要划清 |

## 按需传播流程

```text
publish at edge
  -> register layers
  -> remote subscribe
  -> schedule path
  -> upstream subscribe (needed layers only)
  -> debounce unsubscribe
  -> failover path + keyframe/state rebuild
```

1. 用户在边缘发布；节点注册发布及编码层。  
2. 另一区域出现订阅时，调度计算跨节点路径。  
3. 沿路径建上游订阅，只传该区域需要的最高层或依赖集合。  
4. 下游订阅消失后，防抖 + 保持时间再撤销，避免抖开关。  
5. 链路/节点故障选备用路径，重建标识、反馈与关键帧状态。

若三个边缘都要同一发布，靠近源端复制通常比源端发三份完整跨区流更省出口；复制点自身也要有足够下行。

## 标识与反馈

- 跨节点协议带**稳定发布身份**，不能只靠可能改写的 SSRC。  
- 每段可有独立拥塞控制、序列改写、重传缓存。  
- 下游 NACK 优先最近缓存；不能恢复再逐级向源。  
- 关键帧请求聚合限速；跨区 RTT 大时要判断是否赶得上[[播放截止时间]]。  
- 端到端统计保存**每段链路与映射**，否则只会看到“边缘出站丢包”。

## 调度与故障策略

- 接入综合 RTT、丢包、余量、合规、房间亲和性——不只地理距离。  
- 已建通话是否迁移要权衡中断成本；新用户调到健康节点通常更稳。  
- 跨区链路硬容量 + 准入：过载先降层或限新订阅，避免无限排队。  
- 控制面短暂不一致时，媒体面用租约/代次，防止双路转发与旧路由复活。

## 工程要点

- 每条跨区链路：容量、冗余、重连、回退写进 runbook。  
- 观测能从用户订阅回溯到每一段节点与链路。  
- 故障迁移说明：是否保持 SSRC/序列、是否触发关键帧、旧路径何时释放。  
- 与[[会议媒体路由与订阅]]共用业务发布 ID；级联只多一跳映射。

## 常见故障与验证

| 现象 | 可能原因 |
| --- | --- |
| 同区域正常、跨区卡顿 | 跨区拥塞、选层未下调、反馈 RTT 过长 |
| 切换后重复或跳帧 | 新旧路径重叠、序列/时间戳映射不连续 |
| 一处订阅导致全球复制 | 撤销失败、需求聚合或引用计数错 |
| 边缘故障后长时间黑屏 | 备用未预热、关键帧未请求、旧代次未清理 |
| 指标显示边缘丢包 | 实际损伤在上游某跳，缺分段 Stats |

演练：主动断跨区链路或退出单节点，记录检测、路由收敛、首包、首个可解码帧、体验恢复；确认旧路径资源释放。

## 观测与验收

- **分段指标：** 每跳入/出站码率、丢包、RTT、选层、NACK 终结位置。  
- **控制面：** 路径计算时延、订阅引用计数、撤销是否到期执行。  
- **体验：** 跨区首帧、切人、切网后恢复；对比同区域基线。  
- **容量：** 跨区链路利用率、复制倍数、过载降级是否触发。

## 生命周期（跨区流）

```text
no remote demand
  -> subscribe creates path
  -> layers flow edge↔edge
  -> demand drops (debounce)
  -> teardown
  -> (failover) rebuild with new generation
```


## 容量直觉（跨区）

设源在区域 A，区域 B/C 各有 `S` 个订阅者要同一路高层：

- **坏：** 源向 B、C 各发一份完整跨区流，再在边缘复制。  
- **较好：** A 区核心复制一次到 B、一次到 C，边缘再本地扇出。  
- **订阅消失：** 引用计数归零后再撤跨区，否则会出现“无人看仍占干线”。

把“跨区流条数”和“边缘出站扇出”分列监控，才能看见级联是否真省干线。
