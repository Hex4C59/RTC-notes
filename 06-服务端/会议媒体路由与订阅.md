# 会议媒体路由与订阅

## 一句话说明

会议媒体路由把“谁发布了哪条轨道、谁订阅哪种质量”转换成具体入站流、出站流和反馈路径，是 SFU 房间模型与 RTP 转发状态之间的桥梁。

## 核心机制

- 控制面维护房间、参与者、发布和订阅意图；媒体面将它们绑定到 SSRC、MID/RID、编码层和传输。
- 每个订阅者的可用带宽、终端能力和可见布局都可能产生不同选层结果。
- 反馈必须路由到能实际采取动作的一侧，例如本地重传缓存、上游发布者或编码控制器。

## 核心对象与映射

| 业务对象 | 媒体对象 | 说明 |
| --- | --- | --- |
| 房间 | 媒体节点或级联拓扑 | 决定参与范围与部署位置 |
| 参与者 | 一个或多个传输 | 重连时业务身份可保持，传输会更换 |
| 发布 | Track、Transceiver、MID/RID、SSRC 集合 | 表示一个可被订阅的媒体源 |
| 订阅 | 一个出站 RTP 上下文 | 包含目标编码层、反馈和发送状态 |
| 业务布局 | 优先级和清晰度意图 | 不能直接等同某个固定 SSRC |

业务 ID 必须稳定且可鉴权，协议标识则可能因重协商、切层和重连变化。可靠实现会显式保存两者映射及代次，而不是根据 SSRC 猜用户。

## 发布生命周期

1. 控制面验证权限并创建发布意图。
2. 媒体包到达后，根据 transport、MID/RID、SSRC 和 Payload Type 绑定实际编码。
3. 收齐参数或关键帧后，发布进入可订阅状态。
4. replaceTrack、重新协商或编码层变化会更新映射，但不一定改变业务发布 ID。
5. 停止、超时或传输关闭后撤销路由，并使旧代次反馈失效。

## 订阅生命周期

1. 订阅者提交媒体源、质量、优先级和暂停状态等意图。
2. 路由器结合权限、终端能力、布局和带宽预算选择实际编码层。
3. 为订阅创建出站序列、时间戳、RTCP、重传与 pacing 状态。
4. 布局或网络变化触发选层；切换应等待可解码点并保持输出连续。
5. 取消订阅时停止发包并回收缓存引用、反馈映射和统计对象。

控制请求必须幂等。例如重复的“订阅 A”不应创建两份出站流，迟到的“取消旧订阅”也不能删除重连后创建的新代次。

## 工程要点

- 订阅变更应幂等，并处理流尚未到达、轨道替换和参与者重连。
- 不把业务用户 ID 直接当作协议流标识；两者需要显式映射和生命周期管理。
- 指标至少覆盖发布、订阅、转发链路和选层原因。

## 反馈路由

- 订阅端 NACK 先查本订阅的出站映射与本地包缓存；转发到上游时要恢复入站序列语义。
- PLI/FIR 可跨多个订阅者聚合和限速，避免同时触发关键帧风暴。
- TWCC 描述特定下行传输，主要驱动该订阅者的发送控制，不能直接当成发布上行反馈。
- RTCP Sender Report 的时间映射在改写 SSRC/时间戳时也要保持一致。

## 示例：宫格切换到主讲人

用户原先订阅四路低分辨率缩略图，点击其中一路后，控制面把该发布的优先级和目标尺寸提高。媒体层选择更高 Simulcast 层、请求或等待关键帧，在出站保持序列连续后完成切换；若带宽不足，则保留低层并记录“带宽受限”原因。这个过程同时涉及业务意图、编码层、关键帧和单订阅拥塞状态。

## 常见故障与观测

- 串流或画面归属错误：检查业务 ID、MID/RID、SSRC 与代次映射。
- 取消订阅后仍耗流量：检查路由引用和出站队列是否真正释放。
- 重连后间歇黑屏：检查旧反馈是否污染新传输、首个可解码帧是否到达。
- 选层反复震荡：检查带宽阈值、迟滞、布局优先级和关键帧成本。
- 事件日志应记录发布/订阅状态迁移、原因、旧值/新值和单调时间；媒体指标应记录每条出站的实际层、丢弃原因与队列状态。
