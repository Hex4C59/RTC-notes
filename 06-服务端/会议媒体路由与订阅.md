# 会议媒体路由与订阅

> [!tip] 阅读提示
> **前置：** [[服务端架构地图]]、[[SFU]]；标识见 [[RTP 流标识与复用]]。
> **初读：** 先读「一句话说明」「问题边界」「核心对象与映射」和两个生命周期。
> **深入：** 反馈路由、宫格切换示例与故障表，在串流/选层震荡排障时再读。

## 一句话说明

会议媒体路由把“谁发布了哪条轨道、谁订阅哪种质量”转换成具体入站流、出站流和反馈路径，是 SFU 房间模型与 RTP 转发状态之间的桥梁。它解决的是**意图→媒体绑定**，不是 ICE 连通本身。

## 问题边界

- **上游：** 房间/参与者权限、发布与订阅意图、布局优先级、带宽预算。
- **下游：** 入站绑定、出站 RTP 上下文、选层结果、反馈落到何处。
- **易混淆：**
  - 业务用户 ID ≠ SSRC/MID。  
  - 布局“看大他” ≠ 立刻有高层包（要等可解码点/关键帧）。  
  - TWCC 是**该订阅下行**的反馈，不是发布上行。  
  - 取消订阅成功 ≠ 出站队列/缓存引用一定已释放。

## 核心机制

1. 控制面维护房间、参与者、发布/订阅意图。  
2. 媒体面绑定到 SSRC、MID/RID、编码层与传输。  
3. 每订阅者因带宽、能力、布局不同，选层结果可不同。  
4. 反馈路由到能动作的一侧：本地重传缓存、上游发布者或编码控制。

## 核心对象与映射

| 业务对象 | 媒体对象 | 说明 |
| --- | --- | --- |
| 房间 | 媒体节点或级联拓扑 | 参与范围与部署位置 |
| 参与者 | 一个或多个传输 | 重连时业务身份可保持，传输会换 |
| 发布 | Track、Transceiver、MID/RID、SSRC 集合 | 可被订阅的媒体源 |
| 订阅 | 一个出站 RTP 上下文 | 目标层、反馈、发送状态 |
| 业务布局 | 优先级与清晰度意图 | 不能直接等同某个固定 SSRC |

业务 ID 稳定可鉴权；协议标识会因重协商、切层、重连变化。可靠实现显式保存映射与**代次**，不靠 SSRC 猜用户。

## 发布生命周期

1. 控制面验权并创建发布意图。  
2. 媒体包到达后，按 transport、MID/RID、SSRC、PT 绑定实际编码。  
3. 收齐参数或关键帧后进入可订阅。  
4. replaceTrack / 重协商 / 层变化更新映射，业务发布 ID 可不变。  
5. 停止、超时或传输关闭后撤销路由，并使旧代次反馈失效。

## 订阅生命周期

1. 提交媒体源、质量、优先级、暂停等意图。  
2. 结合权限、能力、布局、带宽预算选实际编码层。  
3. 创建出站序列、时间戳、RTCP、重传与 pacing 状态。  
4. 布局/网络变化触发选层；切换等可解码点并保持输出连续。  
5. 取消时停发包，回收缓存引用、反馈映射、统计对象。

控制请求必须**幂等**：重复“订阅 A”不建两份出站；迟到的“取消旧订阅”不能删新代次。

```text
intent (subscribe A @ high)
  -> authorize + admit
  -> bind outbound context
  -> select layer
  -> wait keyframe / switch
  -> pace + translate feedback
  -> unsubscribe / generation++
```

## 反馈路由

- 订阅端 NACK：先查出站映射与本地缓存；转发上游时恢复入站序列语义。  
- PLI/FIR：跨订阅聚合限速，避免关键帧风暴。  
- TWCC：描述特定下行传输，驱动该订阅发送控制，≠ 发布上行反馈。  
- SR 时间映射：在改写 SSRC/时间戳时保持一致（见 [[SFU RTP 改写与反馈翻译]]）。

## 示例：宫格切换到主讲人

原先订阅四路低分缩略图，点击一路后：

1. 控制面提高该发布优先级与目标尺寸。  
2. 媒体层选更高 Simulcast 层。  
3. 请求或等待关键帧；出站保持序列连续后切换。  
4. 带宽不足则保留低层，并记录“带宽受限”原因。  

同时涉及：业务意图、编码层、关键帧、单订阅拥塞状态——缺任一段都会“点了没变大”或黑一下。

## 工程要点

- 订阅变更幂等；处理流未到、换轨、参与者重连。  
- 业务 ID 与协议标识显式映射 + 生命周期。  
- 指标覆盖：发布、订阅、转发链路、选层原因。  
- 与[[级联与边缘节点]]衔接时，跨区订阅仍用同一业务发布 ID，多一跳路径对象。

## 常见故障与观测

| 现象 | 优先查 |
| --- | --- |
| 串流 / 画面归属错 | 业务 ID、MID/RID、SSRC、代次 |
| 取消后仍耗流量 | 路由引用、出站队列是否释放 |
| 重连后间歇黑屏 | 旧反馈污染新传输、首个可解码帧 |
| 选层反复震荡 | 带宽阈值、迟滞、布局优先级、关键帧成本 |
| 有订阅无包 | 发布未到可订阅、权限、级联路径未建 |

事件日志：发布/订阅状态迁移、原因、旧/新值、单调时间。媒体指标：每条出站实际层、丢弃原因、队列状态。

## 观测与验收

- **正确性：** 订阅矩阵抽样——意图层 vs 实际出站层一致率。  
- **性能：** 切布局到首个高层可解码帧的时延；取消到流量归零时延。  
- **稳态：** 选层震荡次数、关键帧请求速率、出站队列 P95。  
- **故障注入：** 快速重复订阅/取消、换轨、重连、带宽阶跃。

## 选层决策输入（最小集）

| 输入 | 来源 | 若不考虑会怎样 |
| --- | --- | --- |
| 布局优先级 | 控制面 | 缩略图抢高层 |
| 下行带宽估计 | TWCC/BWE | 切大就卡死 |
| 终端解码能力 | 能力协商 | 弱端过载 |
| 依赖层集合 | Simulcast/SVC | 缺底层无法解 |
| 关键帧成本 | 编码器/限速 | 切人风暴 |

路由器输出应可解释：`selected_layer` + `reason`（bandwidth | layout | capability | source_missing）。
