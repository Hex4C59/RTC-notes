PCM → Opus packet → RTP 包

位置手里的数据这一步做什么
采集 / 预处理后PCM 采样块保存随时间变化的数字声音样本，尚未压缩成 Opus
Opus 编码后Opus packet得到压缩音频数据；packet 是编解码格式的名称，尚无 RTP 头
RTP 打包后RTP 包把完整 Opus packet 放入 RTP payload，并加入序列号、时间戳等头字段
判断故障位置：内容听起来失真，先查采集、处理与编码；序号不连续，先查打包后的发送与接收路径。单一现象不能直接证明根因。

边界：这里说的是 RFC 7587 §4 定义的 Opus RTP 负载格式。一个 Opus packet 可含多个 Opus frame；一个 RTP payload 恰好承载一个完整 Opus packet。RTP 包之后还可能经过 SRTP、UDP、IP 等处理。
